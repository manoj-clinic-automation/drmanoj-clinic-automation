**What changes.** (1) On the staff Call Console's **WhatsApp** tab every waiting chat has a **Reply** button. It opens the chat on the page — the newest 30 messages, read only (a photo / PDF / voice note is named, its caption kept). (2) Inside WhatsApp's 24-hour window: a text box, his saved replies as one-tap chips, **Send**. (3) After the window: "only an approved message can go — or call them", with the **Enquiry acknowledgement** (the patient's name filled in, editable) and **Send this message**. (4) Every send goes through `portal_inbox`'s own sender — the same key, the same send log (route `staff-console`), the same 24-hour rule, the same retry of MyOperator's gateway refusal (the server's queue) — signed with the staff login, so his Inbox shows who answered and the chat leaves the waiting list by itself. (5) His **Accept** on a *Call verdict* dispute now reads "Accepted — the verdict was wrong" after the tap (Runbook §2A item 000 (b)).

**Decisions made in the build (stated, not asked):** the reception mobile may reply (it handles the front desk's chats; signed `reception`). The doctor's `?as=` view and any WhatsApp-Inbox login keep the Inbox link exactly as before — no send box for the doctor on this page (his Inbox is his). Guards against two answers, read under ONE write lock with a 'sending' row put in the chat before the send (so two phones on two workers cannot both pass, and a store locked after the send still stops a second one): the same text by the same person within a minute ("Already sent"); another person's answer in the last 2 minutes, or since this person's chat panel was read, with nothing newer from the patient ("Shivani replied since you opened it — read the chat first"); a second approved message after the patient's last message ("already went — call them instead"); the server refuses a template while the window is open. Only a chat the tab listed in the last hour can be read or answered. Templates offered: `PORTAL_STAFF_WA_TEMPLATES` (default `welcome_template`), only those whose single field is the patient's name. `PORTAL_STAFF_WA_SEND = "0"` (or "off" / "no" / "false" — written as a STRING: the portal's own reader treats an int 0 as unset) takes the reply off the page and refuses the routes. A refused send is logged and noted to the clinic Gmail exactly as his Inbox's own are. Nothing in his Inbox page or its routes changes (the block is appended after the page). `VERSION` stays "S951 1.1" (S951's walk pins it); the file carries `KIT_S959`.
