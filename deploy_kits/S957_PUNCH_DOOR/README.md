**What changes.**
1. **The door.** Every punch the machine sent since the source watch began (12-Oct, S535) carried the machine's own mark in one header, one value throughout — 686 punches over 45 days. Its internet address changed 13 times, so the address is not the lock. The listener now admits a punch only when it carries that mark. A punch without it is **kept aside** in `/root/punches_refused.csv` (0600) — never in `punches.csv`, never lost — acknowledged as before, counted in `/root/punch_door.state.json`, and the health page's new line **"punch door"** (Attendance) turns red for a day. Heartbeats and command polls are untouched.
2. **The evidence decides, on the box.** The installer runs the new nightly summary read-only on the live source log and punch file. *ONE MARK* → the door shuts (`enforce`). The mark on every punch but the watch not clean → the door **watches** (every punch stored, one without the mark only counted; the next session reads it). No single mark → the door stays open as before. Then it replays every punch of the last 7 days through the new listener in a temp folder: all must be admitted (else the door only watches), and a punch with the mark removed or wrong must be refused.
3. **The nightly summary** (01:25; rewritten once by the installer right after the swap) no longer writes the mark's value or a full address into `/root/finance/punch_sources_summary.json` (that file travels with the nightly bundle — the value has been in every bundle since 12-Oct; recorded as a finding) — only its length and the first two parts of an address. It also matches a row whose time the listener corrected (S792 keeps the machine's time in the last column) — the 23 "rows without a source line" — the five examples the summary keeps are all of 11-Nov, the day that correction began — are most likely such rows; the installer's evidence run settles it — and leaves refused punches out of the evidence.
4. **presence.py** — who is at the clinic now: punched in today; punched out (an even number of punches, the last at least 120 minutes after the first — a double tap or a re-tap at arrival is not an out; the accepted cost: a double tap at arrival plus a real exit reads as still present); on duty inside the shift (calls_console's own `duty_window`). **The roster stands in** when no punch at all (by anyone) has come by 09:30, or the machine is silent now (a silence-watch failure in the last 30 minutes) — a punch always wins; "by roster" is said; **never on a day the staff register marks the clinic closed**. Settings: `PORTAL_PRESENCE_ROSTER` ("0" = off), `PORTAL_PRESENCE_ROSTER_AFTER` (09:30). Read-only.
5. **The call-back clock** reads the duty through presence.py (its `on_duty` moved there). Unchanged otherwise; presence.py missing → every phone staff login, as for unreadable duty files.

**Decisions made in the build (stated, not asked):** the mark lives in a 0600 file on the box, written from the watch's own evidence; a refused punch is acknowledged (so the machine never jams on it) and kept aside, never discarded; the health line stays red 24 h after a refusal; the door re-reads its file when it changes (no restart to switch modes); the address is recorded with a refusal but never used as the lock. If refused punches were ever genuine (a replaced machine, before its new mark is written): `python3 /root/deploy/repo/deploy_kits/S957_PUNCH_DOOR/door_s957.py readmit` shows the refused rows by day and reason; with `--yes` (and `--since YYYY-MM-DD`) it takes them back into `punches.csv` once each, then the listener is restarted. In watch mode a would-refuse turns the line red too (for the next session to read). The red line is shouted by the health shout (08:05, then hourly 09:35–23:35, once per line per day).
