# MARG & THE MEDICAL PC — the whole subsystem, in three files

**Adopted S203, 26-Aug-2026**, replacing sixty-nine documents that were all equally loud
and none of which superseded the last.

| File | What it is | When you open it |
|---|---|---|
| `MARG_MEDICAL_CURRENT.md` | **everything true now** | always — this is the one you read |
| `MARG_MEDICAL_HISTORY.md` | append-only, indexed | only to answer *"why is it like this?"* |
| `MARG_WALL_CARD.html` | one printed page | it lives beside the medical PC, not on a screen |

This is **D247's own pattern** — a small current register plus an append-only archive —
applied to the one subsystem that never received it.

## The three rules that stop it growing back

1. **New knowledge edits `MARG_MEDICAL_CURRENT.md`.** The replaced text moves into the
   history with its date. **Never a new file.**
2. **A session's output is either a change to CURRENT or an entry in HISTORY.** Session
   records are not canon and are not kept as separate documents.
3. **Anything written to work something out is a WORKING PAPER**, stamped as one when it is
   created, and folded into HISTORY at the close. Nothing gets to become a permanent
   reference by accident. *(Session 203 produced thirteen such papers while consolidating
   away sixty-nine documents. They are in `../S203_MARG_CANON/`, bannered.)*

## Where the old material went

`../S203_MARG_CANON/` — every source document, preserved, hash-listed in its `SUMS.md5`,
each superseded one carrying a banner naming its successor. **Moved, never deleted:** F-89
cost this project three canonical documents permanently, and two more survived only because
a cold backup had them.

## The precedence rule, in one line

**The owner document beats a copy of it. The machine beats both.**
