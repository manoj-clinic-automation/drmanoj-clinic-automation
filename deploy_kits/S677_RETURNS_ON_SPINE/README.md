## Why (`claude/S362_RETURNS_ON_SPINE_BRIEF.md`; the S327 plan's step 6, rung 4d)
- `finance_returns_audit.py` (S212/S213) read `sale_line_item`, an ingest store that S212 itself measured as patchy (123 orphan return lines, 116 return bills with no lines) — hence `find_return_lines`' ladder: bill number flagged; bill number unflagged; the same digits under another prefix; the same day and the money agrees. On the spine a return is one thing: `sp_sale_bill.credit_note = 1` and its `sp_sale_line` rows.
- The charter: one source of truth per section; the returns section's is the spine. Darpan's Vaapsi desk (`returns_desk.py`), which keeps its own `return_line.item_key` history, is **stage 2** (its own kit, with a key migration) — named, not touched.
- `sale_attribution.py` (rung 4e): its tables are read by nothing; retired at rung 5, not moved. `finance_returns.py`'s lookups (`find_patient_sales`, `correlate_return`) have no caller but its selftest — dead, left for rung 5.
