## 2 · The rules (design §3 with the S534 revisions applied)

**2.1 Short in the count.** A row lands in box 1 only from a FRESH count (an old count carried forward is never a write-off; "count first", 22-Nov). Within the allowance (`stock_watch.allowance_units`: `setting` keys `stock.allowance_pct` 1.0 % of the item's own sales since its last count, floor `stock.allowance_min_strips` 1 × pack; `stock.allowance_scale` 2 also exists — A1 reads how S952's judgment applies it and the page shows the allowance figure actually used per row) → the group box.
- **A count made after 17:00 is `awaits` until the day's sale report (S952's `evening_hour`, record_judges.py ~:705): its row shows "waits for today's sales" and offers NO buttons until judged — usually the next morning.** [S534]
- **Write off** → one Stock Issue line on Amir's card (item, quantity; the batch SUGGESTED from Marg's last batch report `stock_batch_now`, nearest expiry first, worded "batch as per the last batch report — Marg's own figure wins"; the judge matches item + units, so a different batch still closes it). The day's write-offs ride one card (one Marg voucher); a card Amir has tapped done never grows. [batch-as-suggestion: S534]
- **Pursue** → a recount on Darpan's next morning list (`stock_watch.ask(con, item, who, sp, mode='next')` with `recount_of`). **End of the road [S534]: recount agrees with Marg → the row closes by itself ("count error"); recount still short → the row returns to box 1 with BOTH counts for his Write off (or a second Pursue).**

**2.2 Closing.** The voucher judge (S965, `voucher_judge.py`) matches every ask to Marg's own report lines (kind + name cut to 15/20/24 with renames + units; line day ≥ ask day − 1; batch exact only for batch fixes). Amir tapped done and no newer report → ONE line on his list: take Marg's Stock Issue + Stock Receive (01-10 → today), once, however many lines wait. A newer report that still lacks it → back on Amir's card by itself: *Ab bana diya* · *Pehle bana chuka hoon* → print the voucher → scanned by reception or by Amir from his card (Kit C). The scan read shows the item on that voucher → closed; not on it → back to Amir as *bana dijiye*. Still unsettled after Amir's second answer and the next report → one line on his list.

**2.3 Nothing old reaches Amir before the whole item is re-judged** (Marg now against the latest count and every bill, sale, voucher and rename since):
1. Marg = shelf → the old ask closes "settled by later entries"; nothing to Amir.
2. Shelf only from an old count (`stock_of_record.base_kind` 'count' + `marg_flag` `old_base`) → recount first on Darpan's next list; the old ask closes as overtaken.
3. A fresh count still differs → ONE correction for TODAY's gap (not the old figure) — via the desk (2.1) or Amir's card.
4. **Only a batch is wrong, the total right → the DESK raises nothing. The Expiry watch (S693, `expiry_watch.py`, nightly on Marg's Batch Stock export) keeps asking Amir as it does today (`stock_batch_fix`; 11 open on his card at 27-Nov); those asks show in box 2 "On its way to Marg" and close by the judge as now. His decision 27-Nov: keep the night asks.** [S534 — replaces the design's "nothing now, the monthly export decides"]
