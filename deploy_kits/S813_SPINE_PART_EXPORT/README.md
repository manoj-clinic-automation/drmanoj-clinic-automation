# S813_SPINE_PART_EXPORT — a part copy of a purchase report may not replace the full one, in the stock record (13-Nov-2026, Sanjeevni session 444)

**The fault (found at the S444 open).** The spine — the pharmacy's stock record that the orders, the expiry page, the stock watch and the stock figure read — has not been rebuilt since **11-Nov 11:10 IST**. Its gate fails at every run: *"every purchase line of an export that is the authority for its whole period belongs to exactly one bill — 66 lines"*. On 11-Nov two bill-wise purchase reports of 1–11 Nov arrived 15 seconds apart, 29 bills and then 4; the spine takes the later one as the authority, so the item lines of 25 bills belong to no bill. S795 put this rule into the purchase pages (F-1277) but not into the spine's own reader.

**The kit.** `/root/finance/spine/spine_build.py` (67d5693f → the TO pin; rebuilt on the box from the live bytes by `make_s813.py`, exact anchors): a later purchase report holding fewer than half the rows of an older report that is the authority for some of its days (one whose period lies inside its own) — and more than two rows short — is a **part list**: it is set aside, the fuller report stays the authority, and `sp_export` says so (`role PART_LIST`, `ok 0`, *part list of …*). `BUILD_VERSION` S813.1. Then the spine is built once, now, by its own cron command, and must come out *BUILT AND SWAPPED*.

**Proof before it left the bench (device VM only; the readings are PHI-free).** The 392 readings of manojz's MargArchive: the live file's build **fails** the gate exactly as the server does; the new file's build **passes**, November's purchase lines 5 → 71, the three part lists it sets aside are the 11-Nov 4-bill list, the 11-Nov 5-line item list, and the 05-Oct Sep–Oct item part list (the same one S811 retired in finance.db, D952). On the readings without the two 11-Nov part lists, the old and new builds are **identical** in every table (only `sp_meta` and that one `sp_export` row differ). `walk_s813.py` 15/15 GREEN; its control on the live file RED (8/15); four mutations each RED. **Cold review by a second reader: SAFE AFTER FIXES** — the must-fix built (the item-line rule also judges a report that the returns witness rescues later); the should-fixes built (only a report that passed its own witness can be the fuller one; a non-blocking gate line names every part list set aside; the installer's restore says truly what happened and checks its own copy). `selftest_spine.py` 71/71 on both. `rehearse_s813.sh` 9/9 on a made-up root (dry · a changed live file · the lock held · the build failing after placing → the old file back · a forced red → back · install · again · the undo line · a kit file altered).
