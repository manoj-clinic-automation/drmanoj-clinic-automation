## 0 · The rules this build stands on

1. **Marg's Excel export is its text page cut into cells at the column heads** (measured: three same-moment pairs of 04-Oct, 4,141 cells, none different). So the text road is ONE cutter and a short spec per report, and its output is the sheet Marg's own Excel export would have been. Nothing downstream learns a new shape; the signatures that type the Excel type the converted sheet.
2. **An empty report is an answer, not a fault (D675 a).** A report whose title, column heads and `*** End of Report ***` are present with zero body rows is VERIFIED as **EMPTY** and lands as that day's legitimate answer. In this kit: the sale bill-wise report (both routes, both readers). Purchase, return, expiry and order empties are *recognised and kept* (never dropped), and named in the report as waiting for a real empty sample before they are verified.
3. **The chain of bill numbers decides what is missing — never the calendar (D675 b).** Marg's sale bills (`A` series) and credit notes (`CN` series) run in unbroken sequence across every closed day (01-Sep → 03-Oct: A3321 → A4000, every Sunday bridged; 20-Sep, a Sunday, had one bill). A no-sale day is a day the chain runs straight through. **Any break — one number or a hundred — is flagged by date and by the exact numbers missing, and that day's sale report must be exported again before the day counts as complete. A gap is never presumed a cancelled bill, never averaged over, never used in a stock figure.** First case on record: A3478 and CN203 between 08-Sep and 09-Sep.
4. **(0.3 is S481's to build; this kit must leave every bill number as Marg printed it in `mi_sale_line` and write the EMPTY day into `mi_file` so the chain can read both.)**
5. **The three live text readers are not rewritten.** `to_rows` (sale), `stock_rows` (closing stock), `order_rows` (order sheet) stay as they are; every text they took before converts to **the same bytes** after this kit (walk §9.1). New kinds go through the cutter.
