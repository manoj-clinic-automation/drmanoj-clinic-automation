## The cause (BL1, C1)
No table uses AUTOINCREMENT, so after the newest machine, paper or reminder is deleted SQLite gives its id to the next
new one. A part/cover row then belongs to a different machine, a spend/part/cover links to a different paper, and the
reminder sync rewrites an `expiries` row the app itself made (the review reproduced: the app's own "Warranty" reminder
became "AMC — …").

## The fix — in `asset_machine.py` only (`asset_register.py` and `sorting_desk.py` and their TO pins stay as they are)
1. **A link is trusted only with its fingerprint.** `asset_part` and `asset_cover` gain `asset_created_at TEXT`
   (the machine's `assets.created_at` when the row was made) and `bill_created_at TEXT` (the paper's `bills.created_at`
   when linked); `service_logs` gains `bill_created_at TEXT` beside `bill_id` (additive, guarded for two workers). A row
   whose machine's or paper's `created_at` no longer matches is **not shown on that machine / as that paper**, and the
   start-up heal **detaches** it — `asset_id = -asset_id` (or `bill_id = NULL`), audited in `desk_audit`, never deleted.
   Rows with a NULL fingerprint (none exist before install) are filled at first sight only when the machine/paper is the
   one they were made with in the same request — otherwise treated as unmatched.
2. **A reminder is S557's own only if all three hold:** its `id` is the row's `expiry_id`, its `entity='asset'` and
   `entity_id` equal the row's machine, and its `label` starts with one of S557's own forms (e.g. "AMC — ", "CMC — ",
   "Warranty — ", "Insurance — ", "Cover — ", "Part warranty — " — read the kit for the exact set and keep them in ONE
   constant). Anything else is never updated or resolved: the row's `expiry_id` is cleared and a fresh reminder created.
   The adoption step keeps the same three tests.
3. **The report §9** (C2) is corrected to say what is true after this fix.
4. **New walk checks, red on the current `asset_machine.py`:** (a) delete the newest machine, create a new one → the
   new one shows no old parts/covers, the app's own reminder for it is untouched, the old rows are detached (negative
   `asset_id`), nothing deleted; (b) delete the newest paper, scan/insert a new one → no part/cover/spend shows it as
   its paper, and its page has no "Linked to" line; (c) an app-made reminder whose id equals a stored `expiry_id` is never
   changed. Plus everything else green as before (S557 38, S555 19, S551 87).
