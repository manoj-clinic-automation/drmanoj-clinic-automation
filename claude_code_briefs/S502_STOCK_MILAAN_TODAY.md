## 0 · The rules this build stands on

1. **A count is never lost, only replaced.** A corrected morning count writes a NEW `stock_point` and marks the old one `status='superseded'` with a note naming its replacement; nothing is deleted. The readers in `stock_watch.py` that sum or pick points skip `superseded` (§2 A3). `shelf_figure.py` (read only here) does not look at status — it takes the newest point by `(at, id)` — and that is safe because a replacement is always newer than the point it replaces (§3 A2 uses 12:01 against 11:58; a live correction uses now). Say so in the report.
1a. **A correction is judged against what was expected when the shelf was counted**, i.e. the old point's own `expected_units` — never a fresh `_s454_expected`, which would take the wrong old point itself as the shelf base and book a false loss (33:7 → 13:7 would read 20 strips short).
2. **The 06-Sep count is sealed.** Darpan's page never writes into it again: `/finance/stockmatch/api/recount` refuses a non-owner (§2 B2). The owner's own recount doors on the Loss desk are untouched.
3. **A loss line that the system no longer believes is voided, not deleted** (`void_at`, `void_why`); a voided line shows nowhere. Its trace is set `status='seen'` with `seen_by='S502'` (the two statuses every reader knows are `open` and `seen`).
4. **Staff words in Roman Hindi; no system jargon on Darpan's page** (no "point", "trace", "pehli ginti", "round").
5. Every edit is an anchored edit on the live bytes (each anchor exactly once, else STOP that file).
